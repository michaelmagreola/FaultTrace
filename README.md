# FaultTrace

**Maintenance knowledge for the plant floor** — semantic search over work-order history with citation-grounded answers and an explicit refusal when nothing reliable matches.

**Demo company:** Cardinal Precision — contract CNC / assembly manufacturer.

---

## Why it exists

Repeat faults are diagnosed from scratch because twenty years of CMMS text uses inconsistent vocabulary (`spindle drift`, `spndl drift`, `SPIN-DRFT`, `axis wander`). Keyword search fails; embedding retrieval finds the same failure in different words. FaultTrace returns a short grounded summary with work-order citations so a technician can act in under two minutes — standing at the machine, on a tablet.

## Features (MVP)

| Area | Capability |
|------|------------|
| Search | Symptom / fault-code query → ranked prior work orders |
| Grounding | Summary of what fixed it, with work-order ID citations |
| Refusal | Explicit “nothing reliable found” when confidence is low |
| Close-out | Structured cause, fix, parts, minutes down — re-embeds on save |
| History | Per-asset work-order timeline + asset-scoped search |
| Supervisor | Recurring faults, downtime, parts to stock, meeting brief |
| Feedback | “Mark useful” on suggested cases (admin audit trail) |
| Auth | Technician / supervisor (planner) / admin roles |
| Safety | Static linked HTML docs — never generated by the model |

## Quick start (local)

**Prerequisites:** Node 20+, Python 3.12+. Docker optional (Postgres).

### One-shot setup (Windows)

```powershell
.\scripts\setup-local.ps1
```

### Manual setup

**1. Backend**

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python -m app.seed
uvicorn app.main:app --reload --port 8000
```

- API docs: http://127.0.0.1:8000/docs  
- Health: http://127.0.0.1:8000/health  

**2. Frontend**

```bash
cd frontend
npm install
npm run dev
```

- App: http://127.0.0.1:5173  

Vite proxies `/api` and `/health` to the backend. Keep the API on port **8000**.

## Environment variables

| File | Purpose |
|------|---------|
| `backend/.env.example` → `backend/.env` | Database, auth mode, AI mode, CORS, retrieval, AWS stubs |
| `frontend/.env.example` → `frontend/.env` | Optional `VITE_API_BASE` when UI and API are on different hosts |

**Never commit `.env` files.** They are gitignored.

### Backend (common)

| Variable | Default | Notes |
|----------|---------|--------|
| `DATABASE_URL` | `sqlite:///./faulttrace.db` | Use Postgres URL when Docker DB is up |
| `AUTH_MODE` | `dev` | `cognito` reserved for next week |
| `SESSION_SECRET` | dev fallback | HMAC secret for signed session tokens (set a long random value) |
| `AI_MODE` | `local` | `bedrock` reserved for next week |
| `CORS_ORIGINS` | Vite localhost origins | Comma-separated; `*` rejected |
| `RETRIEVAL_TOP_K` | `5` | Max neighbors returned |
| `RETRIEVAL_MIN_SCORE` | `0.12` | Below this → refusal |

### Optional Postgres

```bash
docker compose -f infra/docker-compose.yml up -d db
```

Set in `backend/.env`:

```env
DATABASE_URL=postgresql+psycopg://faulttrace:faulttrace@localhost:5432/faulttrace
```

Re-seed: `python -m app.seed`

## Error handling

| Layer | Behavior |
|-------|----------|
| API validation | Pydantic schemas (lengths, ranges); 422 with readable `detail` |
| API runtime | Central handlers in `app/errors.py` for HTTP, DB (503), and unexpected (500) |
| DB sessions | Rollback on exception in `get_db` |
| Frontend | `api.ts` maps network failures and API `detail` into UI banners; React ErrorBoundary + 401 session recovery |

## Responsible AI

- Every answer **cites** work-order IDs used  
- App **refuses** when retrieval confidence is low  
- Safety procedures are **linked**, never generated  
- Technician decides; the model retrieves and drafts
